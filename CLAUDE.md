### (14) 2026-11-08 · Soft-404 fixed: unknown URLs now answer a real 404 instead of 200
- **Measured on production before the change:** `GET https://growlanzo.com/this-route-does-not-exist` → **200**. Root cause: `public/_redirects` carried `/* /index.html 200` (applied before `vercel.json` on Vercel) plus a blanket `/(.*)` rewrite, and `scripts/build.mjs` step 5 *deleted* any `404.html` on purpose. So every typo'd URL looked like a valid page to crawlers and link-checkers.
- **Fix (smallest changes that make the status honest):** the SPA fallback is now an **enumerated allowlist of route segments** — `spa-route-segments.json` (single source), `vercel.json` rewrites (two rules: `/:route(...)` and `/:route(...)/:rest*`), `server.js` (same list, `res.status(404)` + `dist/404.html`), and `scripts/build.mjs` now **writes** `dist/404.html` from the SPA shell with `noindex` instead of deleting it. `public/_redirects` is removed.
- **Why the list and not a regex trick:** a path cannot be both "SPA fallback" and "404". Vercel only emits a 404 when nothing matches, so the segments the router owns must be named. Dynamic public routes (`/freelancers/:id`, `/projects/:id`, `/certificate/:code`) are covered because only the FIRST segment is checked.
- **Guard test:** `src/test/soft404Routing.test.ts` re-derives every `path="…"` segment from `src/app/App.tsx` and fails if `vercel.json` / `spa-route-segments.json` miss one, if a blanket rewrite reappears in either place, if `build.mjs` goes back to deleting `404.html`, or if `server.js` loses its 404 branch.
- **Behaviour split:** known segment → SPA shell with 200 (app renders the page); unknown segment → `404.html` with **404** (app still renders its own `NotFoundPage` inside that shell, `noindex` keeps it out of search).
- Verified locally on the production build (`PORT=4174 node server.js`): `/`, `/pricing`, `/freelancers`, `/dashboard`, `/client`, `/admin`, `/auth/callback`, `/freelancers/some-id` → 200; `/this-route-does-not-exist` → **404**.
